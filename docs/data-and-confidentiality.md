# Evidence, Data & Confidentiality

## What the portfolio shows

Generalized career narratives, documented qualitative outcomes, high-level decision diagrams, and independently written demonstrations with fictional records. A public description is not authorization to reproduce the source behind it.

## What stays out

Employer-owned source code, workbooks, internal documents, source screenshots, data exports, customer/supplier identifiers, actual transactions, prices, inventory, schedules, drawings, specifications, routing rules, technical process parameters, infrastructure, credentials, and controlled or uncertain material.

Exact historical financial and operational results remain in private evidence records until explicit disclosure approval. No original screenshot has been blurred or relabeled for reuse; the public visuals are independently created abstractions or synthetic outputs.

## Evidence labels

- **Documented historical outcome:** supported by career records; not independently audited or employer-attested here.
- **Implemented technical evidence:** source demonstrates functionality; not automatically proof of deployment, adoption, or realized benefit.
- **Working / validation:** implemented components with unfinished acceptance.
- **Design / planned:** requirements or roadmap, not delivered behavior.
- **Synthetic demonstration:** fictional inputs and outputs; never counted as employer results.

## Review rules

Each claim needs a source, supported ownership, a maturity boundary, and a safe public representation. Broad qualitative wording does not authorize reconstructing exact figures through normalized ratios. Public pages link to public portfolio evidence; sensitive source references and discrepancies remain private.

The review covers the current tracked portfolio files. It does not certify external source repositories, employer ownership rights, or prior Git history. New assets need their own review before addition.
